# 演示脚本与分镜

> 产物：`assets/demo.gif`（1000×625，60.0 秒，17 帧，0.8MB）
> 录制：`scripts/record-demo.mjs` 驱动无头 Edge 跑真实后端并抓帧（18 帧，其中两帧画面相同被 GIF 合并）；`scripts/build_demo_gif.py` 合成 GIF
> 录制环境：本地后端 8001 + 前端 5173 + 真实 DeepSeek 调用，**没有任何 mock 数据**
> 界面版本：2026-11-19 重构后的「纸质台账」版式（暖纸底 + 墨线分区 + 单一番茄色）

## 1. 60 秒分镜（对应 GIF 的 17 帧）

| 时间 | 画面 | 讲什么 |
|---:|---|---|
| 0–4s | 空输入框 + 下方四行说明 | 「一个自然语言需求进去，四份结构化产出出来。先说这一屏会给出什么」 |
| 4–6s | 填入需求 | 「零基础 / 每天 2 小时 / 视频偏好 / 三个月内出成果——这四件事分别对应四个字段」 |
| 6–13s | loading 骨架（5 帧） | 「这里在跑 LangGraph：需求提取 → 规划 → 推荐与评估并行。真实耗时 15 秒左右，主要花在三次 LLM 调用上」 |
| 13–21s | 需求分析 + 课程规划概要 | 「五个字段全部填上，没提的用推断并标记；预估周期 8 周 / 112 小时是按每天 2 小时算出来的」 |
| 21–26s | 阶段路径（编号台账） | 「每个阶段一条横线：序号、阶段名、右侧时长、下面学习内容和阶段目标。不是一句『先学基础』」 |
| 26–30s | 资源 + 检索来源 | 「标题右边这行是来源：知识库、匹配度 87%、有没有联网。细节收在『检索详情』里，不占正文」 |
| 30–34s | 评估：整体 + 四维 | 「整体 8.5，可行性 9、内容 9、时间 8、方法 8；均分低于 6 分会自动回到规划重生成」 |
| 34–36s | 反馈表单 | 「点评价此资源」 |
| 36–39s | 打 5 星 | 「评分必选，否则提交会被前端拦下」 |
| 39–42s | 评分回写 | 「提交后这条立刻变成 5.0 分 / 1 条反馈——这是真写进 Chroma 的元数据，不是前端假状态」 |
| 42–60s | 整体回看 | 收尾：一句定位 + 指到评测报告 |

**讲述要点**：全程只讲「用户看到了什么」和「这一步背后是谁在算」，不念技术名词。

## 2. 三个用例（都是实测输出，不是设想）

### 用例 A：零基础学 Python（GIF 用的就是这条）

```text
我是零基础，每天能学2小时，想用视频学 Python 编程，希望三个月内能做出一个小项目
```

| 产出 | 实测值（2026-11-20 录制这一轮） |
|---|---|
| 需求五字段 | 学习目标「学习Python编程」/ 零基础 / 2 小时 / 视频 / 标准学习 |
| 计划 | 4 个阶段，各 2 周（28h）：Python基础入门 → 函数与模块化编程 → 面向对象与常用库 → 项目实战 |
| 周期 | 约 8 周（56 天），总学习时长约 112 小时 |
| 资源 | `Python基础教程`（相似度 0.50 / 重排置信度 73%），共 1 条 |
| 检索来源 | 知识库 1 个 · 匹配度 87% · 未联网 · 检索详情里为质量「高」· Cross-Encoder 已重排 |
| 评估 | 整体 8.5，可行性 9 / 内容 9 / 时间 8 / 方法 8 |

**讲解点**：这是「知识库命中且排序正确」的最优路径——资源来自 `knowledge_base`，相似度与置信度都标在行上，可以当场解释为什么它排 #1。**注意条数会变**：同一句话换一次运行，LLM 可能给 1 条也可能给 2 条（另一次实测是 `Python基础教程` + `哈佛CS50计算机科学导论`），这是模型输出的浮动，不是检索丢结果。

### 用例 B：数学进阶（有基础、要打底、只看文字）

```text
我有微积分和线性代数基础，每天能学1.5小时，想系统学概率论与数理统计，为后面学机器学习打底，喜欢看文字资料
```

| 产出 | 实测值 |
|---|---|
| 需求五字段 | 「系统学习概率论与数理统计，为机器学习打底」/ 中级 / 1.5 小时 / 文字 / 长期学习 |
| 周期 | 约 4.5 个月（18 周），约 189 小时 |
| 资源 | `动手学深度学习预备数学`（0.511）、`斯坦福概率论CS109`（0.507）——都属数学/AI 交叉，不算跑偏 |
| 检索诊断 | 知识库 2 个 · 匹配度 61% · 质量「中」· 候选 2 条 |
| 评估 | 整体 8.2 |

**讲解点**：同样一句话，难度从「零基础」变「中级」、时间期望从「三个月」变「长期」，计划周期和资源排序都跟着变——说明需求提取不是走过场，是真的驱动下游。**注意**：匹配度 61% 属「中」档，质量门控判通过但没触发改写，这是阈值口径问题，见下方「预设追问」。

### 用例 C：时间紧的高阶目标（这条要如实讲短板）

```text
我有 Python 和 PyTorch 基础，两周内要能自己搭一套 RAG 检索问答系统做内部知识库，每天能投入3小时，只看文档和代码
```

| 产出 | 实测值 |
|---|---|
| 需求五字段 | 「搭建一套RAG检索问答系统做内部知识库」/ 中级 / 3 小时 / 文字 / 短期学习 |
| 周期 | 3 周（共 63 小时）——注意：用户说「两周」，系统按每天 3 小时算出 3 周，属于**没有对齐用户的硬约束** |
| 资源 | `LangChain官方文档`（0.560）✅、`TypeScript官方手册`（0.516）❌、`动手学深度学习PyTorch版`（0.511）△、`动手学深度学习预备数学`（0.544）△、`React官方学习文档`（0.504）❌ |
| 检索诊断 | 知识库 5 个 · 匹配度 64% · 质量「中」· 候选 10 条 |
| 评估 | 整体 8.5 |

**讲解点（建议主动说，别等面试官问）**：
- 60 条知识库里没有 RAG 工程实践类资源，相似度全部挤在 0.50–0.56，**排序区分度已经失效**；
- 质量门控只判到「中」（0.55 阈值），所以没有触发查询改写或联网补充；
- 这两条是本项目已知的边界：**覆盖率不足时应该主动说「库里没有」而不是硬凑 5 条**。改进方向写在 `RETRIEVAL_EVAL.md` 的后续工作里（相关性下限 + 拒答路径 + 按语料校准质量阈值）。

主动暴露这个缺口，比让面试官自己发现要好——它同时证明你知道指标该怎么用。

## 3. 常见追问与回答

| 追问 | 回答 |
|---|---|
| 有线上地址吗？ | 没有，纯本地运行，仓库里不含任何托管平台配置。演示就是这段 GIF，命令三行能跑起来 |
| 为什么要四个 Agent，串行不行？ | 推荐和评估互不依赖，并行省一半时间；评估不达标要回到规划重生成，串行写法会把这层判断埋进主流程 |
| 13 秒是不是太慢？ | 三次 LLM 调用，检索本身 10ms、重排 360ms，剩下全是模型推理。真要压时间，做法是流式输出 + 需求提取用更小的模型 |
| 重排为什么是负收益？ | 60 条语料的候选池太小，Cross-Encoder 把小样本噪声放大了；加了置信度门控后从 −0.02 变 +0.01，详见 `RETRIEVAL_EVAL.md` 3.3 |
| `answer_relevancy` 为什么只有 0.49？ | 被评测的 `response` 是资源清单模板而不是自然语言回答，RAGAS 反推问题时质量差。这个指标对当前任务参考价值有限，我在报告里标了 |
| 知识库只有 60 条，是不是玩具？ | 是自建的，覆盖 AI / 编程 / 数学三类。它的作用是把链路做对并量化——用例 C 正好暴露了覆盖率不足时的退化行为，而这类问题在小库上才看得清 |
| 反馈真的有用吗？ | 有用但只到「评分与条数」：写回 Chroma 元数据、检索结果里带出来、刷新可见；**没有**参与排序加权，这是已知限制 |

## 4. 重新录制

```powershell
# 1. 起后端与前端（两个终端，分别在两个分区里执行）
cd backend
.\.venv-run\Scripts\python.exe -B -m src.api.api_server   # http://localhost:8001

cd ..\frontend
npm run dev                                                # http://localhost:5173

# 2. 备份反馈状态（录制会真写一条反馈）
copy backend\data\feedback_records.json %TEMP%\demo_backup\feedback_records.json

# 3. 抓帧（回到仓库根执行，可换输入，默认就是用例 A）
cd ..
node scripts/record-demo.mjs "我是零基础，每天能学2小时，想用视频学 Python 编程"

# 4. 合成 GIF
python scripts/build_demo_gif.py --frames "$env:TEMP\demo_frames" --out assets/demo.gif

# 5. 还原：反馈 JSON 拷回原处；再把 chroma 里那条资源的 rating / feedback_count 改回 0.0 / 0
```

几点实测经验：

- **演示会写入真实反馈**（`backend/data/feedback_records.json` 多一条，**Chroma 里那条资源的 `rating` / `feedback_count` 也会被改写**）。两处都要还原，否则下一次录的时候卡片上已经带着 5.0 星，看着不像首次使用。还原 Chroma 要先停后端再改，避免两个进程同时写一个 PersistentClient。
- 无头浏览器必须用 `--headless=old`：本机 `--headless=new` 截出来是全白图。
- GIF 用逐帧自适应调色板（`--palette frame --colors 200`）：全局单板会把浅色按钮压成灰块。暖纸底是纯色，量化后体积反而小（2.9MB → 0.8MB）。
- 帧间隔取录制时的真实时间差并夹在 1.8–5 秒；总时长不足 60 秒时逐帧补，不能只加在最后一帧。
- 脚本按**界面上的文案和类名**定位（`.result` / `.stars__btn` / `评价此资源` / `已记下`），改版后这几个锚点变了就会超时，改版后先跑一次再合成。
