## 1. 60 秒分镜（对应 GIF 的 16 帧）

| 时间 | 画面 | 讲什么 |
|---:|---|---|
| 0–4s | 空输入框 | 「一个自然语言需求进去，四份结构化产出出来。先说我输入的是什么」 |
| 4–7s | 填入需求 | 「零基础 / 每天 2 小时 / 视频偏好 / 三个月内出成果——这四件事分别对应四个字段」 |
| 7–31s | loading（5 帧） | 「这里在跑 LangGraph：需求提取 → 规划 → 推荐与评估并行。真实耗时 15 秒左右，主要花在三次 LLM 调用上」 |
| 31–34s | 需求分析 + 课程规划 | 「五个字段全部填上，没提的用推断并标记；预估周期 8 周 / 112 小时是按每天 2 小时算出来的」 |
| 34–37s | 学习路径 4 阶段 | 「每个阶段有周数、学时、学习内容、阶段目标，不是一句『先学基础』」 |
| 37–40s | 资源 + 诊断条 | 「重点看这条：来源=知识库、匹配度 75%、质量=高、候选 2 条、Cross-Encoder 已重排。链路每一步都可解释」 |
| 40–43s | 六维评估 | 「评估 Agent 给 8 分左右，可行性 9、内容 8；低于 6 分会自动回到规划重生成」 |
| 43–45s | 反馈表单 | 「点评价此资源」 |
| 45–48s | 打 5 星 | 「评分必选，否则提交会被后端拒绝」 |
| 48–51s | 评分回写 | 「提交后卡片立刻变成 5.0 分 / 1 条反馈——这是真写进 Chroma 的元数据，不是前端假状态」 |
| 51–60s | 整体回看 | 收尾：一句定位 + 指到评测报告 |

**讲述要点**：全程只讲「用户看到了什么」和「这一步背后是谁在算」，不念技术名词。

## 2. 三个用例（都是实测输出，不是设想）

### 用例 A：零基础学 Python（GIF 用的就是这条）

```text
我是零基础，每天能学2小时，想用视频学 Python 编程，希望三个月内能做出一个小项目
```

| 产出 | 实测值 |
|---|---|
| 需求五字段 | 学习目标「学习Python编程并做出一个小项目」/ 零基础 / 2 小时 / 视频 / 标准学习 |
| 计划 | 4 阶段：基础语法与编程思维 2 周（28h）→ 核心进阶与模块化 2 周（28h）→ 项目实战 3 周（42h）→ 项目完善与总结 1 周 |
| 周期 | 约 8 周（56 天），总学习时长约 112 小时 |
| 资源 | `Python基础教程`（相似度 0.73 / 重排置信度 73%）→ `哈佛CS50计算机科学导论`（0.50 / 50%） |
| 检索诊断 | 知识库 2 个 · 匹配度 75% · 质量「高」· 候选 2 条 · Cross-Encoder 已重排 |
| 评估 | 整体 8+，可行性 9 / 内容 8 / 时间 8 / 方法 9 |

**讲解点**：这是「知识库命中且排序正确」的最优路径——两条资源都是 `knowledge_base` 来源，相似度与置信度都标在卡片上，可以当场解释为什么 #1 在 #1。

### 用例 B：数学进阶（有基础、要打底、只看文字）

```text
我有微积分和线性代数基础，每天能学1.5小时，想系统学概率论与数理统计，为后面学机器学习打底，喜欢看文字资料
```

| 产出 | 实测值 |
|---|---|
| 需求五字段 | 「系统学习概率论与数理统计，为机器学习打底」/ 中级 / 1.5 小时 / 文字 / 长期学习 |
| 周期 | 约 4.5 个月（18 周），约 189 小时 |
| 资源 | `动手学深度学习预备数学`（0.511）、`斯坦福概率论CS109`（0.507）——都属数学/AI 交叉，不算跑偏 |
| 检索诊断 | 知识库 2 个 · 匹配度 61% · 质量「中」· 候选 2 条 |
| 评估 | 整体 8.2 |

**讲解点**：同样一句话，难度从「零基础」变「中级」、时间期望从「三个月」变「长期」，计划周期和资源排序都跟着变——说明需求提取不是走过场，是真的驱动下游。**注意**：匹配度 61% 属「中」档，质量门控判通过但没触发改写，这是阈值口径问题，见下方「预设追问」。

### 用例 C：时间紧的高阶目标（这条要如实讲短板）

```text
我有 Python 和 PyTorch 基础，两周内要能自己搭一套 RAG 检索问答系统做内部知识库，每天能投入3小时，只看文档和代码
```

| 产出 | 实测值 |
|---|---|
| 需求五字段 | 「搭建一套RAG检索问答系统做内部知识库」/ 中级 / 3 小时 / 文字 / 短期学习 |
| 周期 | 3 周（共 63 小时）——注意：用户说「两周」，系统按每天 3 小时算出 3 周，属于**没有对齐用户的硬约束** |
| 资源 | `LangChain官方文档`（0.560）✅、`TypeScript官方手册`（0.516）❌、`动手学深度学习PyTorch版`（0.511）△、`动手学深度学习预备数学`（0.544）△、`React官方学习文档`（0.504）❌ |
| 检索诊断 | 知识库 5 个 · 匹配度 64% · 质量「中」· 候选 10 条 |
| 评估 | 整体 8.5 |

**讲解点（建议主动说，别等面试官问）**：
- 60 条知识库里没有 RAG 工程实践类资源，相似度全部挤在 0.50–0.56，**排序区分度已经失效**；
- 质量门控只判到「中」（0.55 阈值），所以没有触发查询改写或联网补充；
- 这两条是本项目已知的边界：**覆盖率不足时应该主动说「库里没有」而不是硬凑 5 条**。改进方向写在 `RETRIEVAL_EVAL.md` 的后续工作里（相关性下限 + 拒答路径 + 按语料校准质量阈值）。

主动暴露这个缺口，比让面试官自己发现要好——它同时证明你知道指标该怎么用。

## 3. 常见追问与回答

| 追问 | 回答 |
|---|---|
| 有线上地址吗？ | 没有，纯本地运行，仓库里不含任何托管平台配置。演示就是这段 GIF，命令三行能跑起来 |
| 为什么要四个 Agent，串行不行？ | 推荐和评估互不依赖，并行省一半时间；评估不达标要回到规划重生成，串行写法会把这层判断埋进主流程 |
| 13 秒是不是太慢？ | 三次 LLM 调用，检索本身 10ms、重排 360ms，剩下全是模型推理。真要压时间，做法是流式输出 + 需求提取用更小的模型 |
| 重排为什么是负收益？ | 60 条语料的候选池太小，Cross-Encoder 把小样本噪声放大了；加了置信度门控后从 −0.02 变 +0.01，详见 `RETRIEVAL_EVAL.md` 3.3 |
| `answer_relevancy` 为什么只有 0.49？ | 被评测的 `response` 是资源清单模板而不是自然语言回答，RAGAS 反推问题时质量差。这个指标对当前任务参考价值有限，我在报告里标了 |
| 知识库只有 60 条，是不是玩具？ | 是自建的，覆盖 AI / 编程 / 数学三类。它的作用是把链路做对并量化——用例 C 正好暴露了覆盖率不足时的退化行为，而这类问题在小库上才看得清 |
| 反馈真的有用吗？ | 有用但只到「评分与条数」：写回 Chroma 元数据、检索结果里带出来、刷新可见；**没有**参与排序加权，这是已知限制 |

## 4. 重新录制

```powershell
# 1. 起后端与前端（两个终端）
cd learning-planning-multi-agent
.\.venv-run\Scripts\python.exe -B api_server.py       # http://localhost:8001
npm run dev                                            # http://localhost:5173

# 2. 抓帧（可换输入，默认就是用例 A）
node scripts/record-demo.mjs "我是零基础，每天能学2小时，想用视频学 Python 编程"

# 3. 合成 GIF
python scripts/build_demo_gif.py --frames "$env:TEMP\demo_frames" --out assets/demo.gif
```

几点实测经验：

- **演示会写入真实反馈**（`data/feedback_records.json` 会多一条，资源评分会变）。录之前备份、录完还原，否则第二次录的时候卡片上已经带着上一轮的星级，看着不像首次使用。
- 无头浏览器必须用 `--headless=old`：本机 `--headless=new` 截出来是全白图。
- GIF 用逐帧自适应调色板（`--palette frame --colors 200`）：全局单板会把浅色按钮和渐变色头压成灰块。
- 帧间隔取录制时的真实时间差并夹在 1.8–5 秒；总时长不足 60 秒时逐帧补，不能只加在最后一帧。
